Stability tiers

Vertep is version 0.1.x and its parts are not equally mature. Each crate and package declares a tier in its manifest, and the tables below and in the README are generated from those declarations, so they cannot say more than the manifests do.

What a tier means

TierEvidence behind itWhat to expect
stableChecked against a reference from outside its own tests: the W3C SCXML conformance suite, the Lean model as a differential oracle, or the storage contract kit. Used by the examples that are held to their recorded output.Behaviour you can rely on. Before 1.0 a minor version may still change an API, and the CHANGELOG says so.
previewWell tested and used by examples or bindings, but with no outside reference, with recent large changes, or with open tasks in its milestone.Works for the documented cases; expect API changes and gaps that the docs pages name.
experimentalSpecified and tested by its own suite, sometimes with a Lean model, but with open items on the roadmap and no user outside the project yet.Try it, report what breaks, and do not build on it unaided.

A tier moves up when the evidence changes: an outside reference, a user outside the project, or its open tasks closed. The reasons below are one line each; the docs page of each part names its gaps in full.

How the tables are kept

A crate declares its tier in Cargo.toml, an npm package in its package.json, and the Python package in pyproject.toml:

[package.metadata.vertep]
tier = "stable"
tier-reason = "W3C SCXML IRP suite in CI, ..."
"vertep": { "tier": "preview", "tierReason": "..." }

python3 site/tools/tiers.py rewrites the table on this page and in the README. CI runs it with --check, which fails when a crate or package declares no tier, names an unknown one, or when a table differs from the manifests.
