## 6. Fault injection and verification

- [x] 6.1 Build a Jepsen-style harness that runs a multi-node cluster in-process and in containers, injecting network partitions, one-way packet loss, process pauses, crashes, restarts and clock skew beyond the safety margin
  - Done 2026-11-11: besides the in-process harness, `tests/containers.rs` runs four `vertep-fault-node` processes (feature `fault-node`, built for Linux in `rust:1.95.0-slim-bookworm` into a cached volume, run in `debian:bookworm-slim`) on etcd or k3s membership, with the world (client messages, the fenced store, receivers, the history) in the test process. Partitions are `docker network disconnect` from the authority's network, pauses `docker pause`, crashes and restarts `docker kill` and `docker start`; clock skew runs one node's lease clock at half speed (containers share the host clock); one-way loss uses `tc netem` where the kernel has it and otherwise drops that node's side-effect datagrams at the receiver, because Docker Desktop's kernel has neither netem nor the iptables `statistic` match. Histories pass the checker and the Lean lease model in strict mode on both memberships.
- [x] 6.2 Write a history checker that verifies every actor journal is linear, no journal version holds two entries, every acknowledged message was processed exactly once, and no fenced side effect was accepted; annotate the fault-injection test `@tg: verifies:: [[openspec:shard-placement#Single Activation Guarantee#Fault injection never yields two writers]] {level: e2e}`
- [x] 6.3 Run the harness against each membership implementation (static, gossip, etcd, Kubernetes) and against replication factors 1 and 3 in nightly CI
  - Done 2026-11-11: `tests/faults.rs` is generic over the membership (static, the external stand-in and gossip on simulated time; etcd and Kubernetes in containers on real time) and the journals (one shared fenced store; local journals with replication factor 1, or 3 with both standbys required), and every history replays through the Lean lease model in strict mode. The nightly `cluster-faults` job runs the matrix, `tests/external.rs` and the container harness with `VERTEP_CONTAINER_TESTS=require` and `--features differential,etcd,kubernetes`. The matrix found three bugs, each fixed with a failing test first: a restarted gossip leader granting an epoch it had already granted (now a per-start epoch tag and epochs kept across leadership terms), standby replicas raising their fence on batches that stored nothing, and owners writing their own copy before checking the replication quorum.
- [x] 6.4 In `vertep-lean`, model shard leases, epochs, fenced appends and replication receivers, and prove that for every shard and epoch at most one writer's appends are accepted and that accepted journal versions are totally ordered across epochs; no `sorry`, axioms pinned in tests — OPEN: owned by the Lean work in `lean/`
- [x] 6.5 Use the Lean lease and fencing model as a differential oracle: replay histories recorded by the fault-injection harness through it and require identical accept and reject decisions
  - Done 2026-11-11: the harness records every grant, including those `Membership::tick` acquires for a node (shards the view hands to it, leases it learns again after a rejoin), and `fault_injection_history_is_linear_once_and_unfenced` replays each seed's history through `vertep-lease` in strict mode (no `--infer-grants`) via `LeanTools::lease`; all 11,241 decisions on the five seeds agree. The test skips the replay when the Lean executable is not built, unless the `differential` feature of `vertep-cluster` requires it, as the nightly `cluster-faults` job now does after building the Lean package.
